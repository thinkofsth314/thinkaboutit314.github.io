# 小项目1：3-SAT问题


## 一、解题思路

### 1. 问题分析与初步想法

本题要求给 n 个布尔变量赋值，使 m 个表达式同时为真。每个表达式由三个项通过逻辑“或”连接，每一项是一个变量或该变量的取反。以下将每个这样的表达式称为一个“子句”。

使用 1 表示真，0 表示假。例如：

    x₁ ∨ ¬x₂ ∨ ¬x₄

为真的条件等价于：

    x₁ + (1 − x₂) + (1 − x₄) ≥ 1

因此，**检查一个子句时，只要发现其中一项为真，就能确定该子句已经满足**。

暴力算法是是枚举全部 2ⁿ 种赋值，逐一检查每组赋值是否满足所有子句。由于每个子句只有三项，检查一组赋值需要 O(m) 时间，因此直接枚举的最坏时间复杂度为 O(m · 2ⁿ)。

不同子句可能包含相同的变量，所以不能逐个子句独立选择赋值。一个变量的选择可能同时满足某些子句，又使其他子句更难满足，需要从整体上进行搜索。一个初步的想法是让出现次数为权重决定赋值尝试的先后（见后文的冲突学习部分）。

### 2. 利用部分赋值提前判断

直接枚举是在所有变量都赋值后才检查结果，但实际上，在部分变量已经赋值时，就可能得到有用的信息。

对于一个子句：

- 如果至少有一项为真，该子句已经满足；
- 如果所有项都为假，当前赋值产生冲突；
- 如果其他项均为假，只剩下一项尚未确定，则最后一项必须为真；
- 如果没有真项，且至少两项尚未确定，则暂时无法进一步判断。

因此，可以一边赋值，一边检查和推导。出现冲突时立即停止当前尝试，不再枚举该分支下剩余变量的取值。


### 3. 单子句传播：优先进行必然的推导

如果一个子句只剩下一项尚未确定，其他项均为假，那么这最后一项必须为真。这种推导称为**单子句传播**。[1]

例如：

    x₁ ∨ ¬x₂ ∨ x₃

已知 x₁ = 0、x₂ = 1，那么前两项都为假，因此必须令 x₃ = 1。

新确定的赋值还可能使其他子句只剩下一项尚未确定，从而产生更多的单子句。因此，每次主动选择变量后，都反复进行单子句传播，直到无法继续推导，或者发生冲突。

这些赋值是当前条件下必须成立的结果，不需要分别尝试两个取值，可以减少主动搜索的次数。


### 4. 分支搜索：无法进行必然推导时，进行尝试

如果无法继续传播，而且仍有子句未满足，就选择一个尚未赋值的变量，尝试将其设为 0 或 1，再继续传播。

基本的回溯方法是：先搜索其中一个取值对应的分支；如果该分支失败，就撤销该次选择及其后续推导，再尝试另一个取值。

单子句传播与这种分支搜索结合，构成 DPLL 算法的核心框架。[1]

但单纯回溯可能在不同分支中重复遇到由同一原因导致的冲突。为了减少这种重复搜索，进一步考虑冲突驱动子句学习，即 CDCL。


### 5. 冲突学习：从失败中获得新的约束条件

出现冲突后，不仅撤销当前赋值，还分析哪些选择共同导致了冲突，并将它们不能同时成立这一事实写成新的子句。[1]

例如，假设当前存在以下约束：

    ¬a ∨ b
    ¬c ∨ d
    ¬b ∨ ¬d
    

如果选择 a = 1、c = 1，那么：

1. 第一条要求 b = 1；
2. 第二条要求 d = 1；
3. 第三条要求 b 和 d 不能同时为 1。

因此产生冲突，可以推出：

    a 和 c 不能同时为 1

也就是：

    ¬a ∨ ¬c

将这条新子句加入后，后续搜索就能更早避开同样的错误。例如，当 a = 1 时，可以直接推出 c = 0。

这种新加入的子句称为**学习子句**。它由已有约束推导而来，因此不会排除原问题的任何可行解。


### 6. 根据冲突原因回退

发生冲突后，先推导出一条新的约束，再根据它确定需要退回的位置，不必逐层尝试所有选择。

例如，依次选择 a = 1、b = 0、c = 1、d = 1 后发生冲突，并推出：

    ¬a ∨ ¬d

这说明 a、d 不能同时为 1，改变 b、c 也无法解决这个矛盾。因此，可以直接退回选择 a = 1 之后，撤销后续赋值，再由新约束推出 d = 0，继续搜索。

加入新的约束条件之后，撤销一些原来对变量的赋值，让新加的约束条件只剩下一个变量未确定，其他都为假。即让这个新约束条件成为单子句[1]

如上例，则保留a=1，撤销d的赋值，变为 0 ∨ ¬d。此时d必须为0.


### 7. 根据冲突分析设置每个变量的权重，依次尝试赋值

无法继续推导时，选择一个未赋值变量进行尝试。为改善搜索顺序，给每个变量设置一个分数：

- 变量参与冲突分析时，提高它的分数；
- 逐渐减弱较早冲突带来的分数；
- 每次优先选择分数最高的未赋值变量。

这样可以优先处理近期经常导致冲突的变量，争取更早发现不合适的选择。

分数只决定先处理哪个变量，不决定它取 0 还是 1。这种方法可能减少实际搜索量，但不保证每次选择都是最优的。[1][2]


### 8. 整体求解流程

1. 初始时，所有变量均未赋值。
2. 给单子句赋值：如果其他项都为假，只剩一项未确定，就令这一项为真，并反复推导。
3. 如果发生冲突，就分析原因，加入由此推出的新约束，撤销相应赋值，再继续推导。
4. 如果没有冲突，但仍有子句未满足，就选择分数最高的未赋值变量，尝试一个取值，然后返回第 2 步。
5. 如果所有子句都已满足，就将剩余未赋值变量任意补全，检查并输出答案。



### 9. 方法的正确性与效率说明

该方法不会遗漏可行解，原因如下：

- 能直接推出来的赋值，在当前选择下必须满足所在子句为真；
- 如果某条子句已经全部为假，那么继续给剩下的变量赋值也无法解决问题，故此时加新约束条件并撤回某些变量的赋值是合理的；
- 新加入的约束是从原有条件推出来的，所有正确答案本来就满足它；
- 回退只是撤销之前的尝试，再继续寻找其他可能的赋值。

相比逐一枚举，这个方法能直接推导出一部分变量的值，发现走不通时提前回退，并记住冲突的原因，减少重复尝试。

### 10. 时间复杂度分析

设有 n 个变量，搜索过程中所有子句的总项数最多为 L，一共进行 T 轮“传播及后续处理”。

采用逐条扫描的方法时，检查全部子句需要 O(L) 时间。一轮传播最多确定 n 个变量，因此需要 O(nL) 时间；选择变量和回退需要 O(n) 时间，冲突分析采用简单实现时需要 O(n²) 时间。

因此，总时间上界可写为：

    O(T · (nL + n²))

最初 L = 3m，加入新约束后 L 会增大。该方法可以减少实际搜索次数，但最坏情况下仍可能需要指数级搜索。

## 二、难点分析

### 1. 多个子句之间的变化并不独立

同一个变量可能出现在多个子句中，而且可能在一些子句中以原变量出现，在另一些子句中以取反形式出现。

因此，使一个子句成立的赋值，可能使其他子句产生新的限制，甚至发生冲突。不能独立求解各个子句，而需要始终维护一组全局一致的赋值。

解决方法是：每次赋值后进行单子句传播，检查这一变化对其他子句的影响；如果发现冲突，就调整此前的选择。



### 2. 怎么从冲突中提取正确的学习子句

发现某条子句全部为假，只能说明当前赋值存在矛盾。更关键的问题是：哪些赋值共同导致了这个矛盾？

如果直接禁止冲突子句中涉及的变量取某个值，可能错误地排除可行解。因此，学习子句必须由已有约束严格推导出来。

冲突分析使用的基本规则是归结。例如：

    A ∨ x
    B ∨ ¬x

可以推出：

    A ∨ B

因为如果 A 和 B 都为假，前两条就会分别要求 x 为真和为假，产生矛盾。这里 A、B 可以各自代表若干项的“或”。

解决方法是：从冲突子句出发，结合传播赋值的原因，逐步消去中间推导涉及的变量，得到能够解释冲突的新约束。

### 3. 确定冲突分析的停止位置和回退位置

冲突发生后，如果回退得太少，可能无法解除冲突；如果回退得太多，则会撤销本来可以保留的搜索结果。

本方案采用 First-UIP 方法：按赋值顺序逆向分析冲突，直到学习子句中只剩一个属于当前决策层的项。

随后，回退到学习子句中其他项所属决策层的最大值；如果没有其他项，则回到第 0 层。

这样，回退后其他项仍为假，而当前层的那一项变为未确定，因此学习子句能够立即推出新的赋值。

这一部分的关键是保证冲突分析、决策层判断和回退位置相互一致。

### 4. 回退后正确恢复搜索状态

回退不仅需要撤销主动选择的赋值，还需要撤销被回退决策层中的全部推导赋值。

如果只修改决策变量，却保留依赖旧前提的推导结果，后续搜索就可能在错误状态下继续进行。

解决方法是：回退时统一撤销目标层之后的赋值，并清除这些赋值对应的原因和决策层信息。

学习子句则需要保留。它们是原问题约束的逻辑结论，不依赖被撤销的选择仍然成立，可以继续用于后续搜索。

### 5. 选择有效的搜索顺序

不同的变量选择顺序可能带来很大的运行时间差异，但无法仅根据变量出现次数就判断哪一种顺序最好。

解决方法是：使用动态评分，让近期经常参与冲突分析的变量获得更高优先级，同时逐渐减弱较早冲突的影响。

实现时还需要控制评分的数值范围。如果评分不断增大，可以对所有评分及后续加分幅度按相同比例缩小，避免数值溢出，同时保持变量之间的优先顺序。

这种评分用于提高实际搜索效率，但不作为判断某个赋值是否正确的依据。

## 三、使用的数据结构

本方案主要使用数组和 vector(方便在搜索过程中追加新的子句).

### 1. 子句集合

使用 `vector<vector<int>>` 保存所有子句，每个内部 vector 保存一条子句。

沿用输入的表示方式：正数表示原变量，负数表示取反。例如，`{1, -2, -4}` 表示：

    x₁ ∨ ¬x₂ ∨ ¬x₄

新推导出的子句追加到集合末尾，原有子句的编号保持不变。

### 2. 变量信息数组

按变量编号保存以下信息：

| 数组 | 保存的内容 | 用途 |
| --- | --- | --- |
| `value` | 当前取值：-1 表示未赋值，0 表示假，1 表示真 | 判断子句是否满足 |
| `level` | 变量在第几次主动选择及其后续推导中被赋值 | 确定回退时撤销哪些赋值 |
| `reason` | 推出该赋值的子句编号，主动选择的赋值记为 -1 | 追查冲突原因 |
| `score` | 变量的评分 | 优先选择分数较高的未赋值变量 |

其中，`value` 中的 -1 表示未赋值，与子句中负数表示取反是不同的含义。

### 3. 赋值记录

使用一个 `vector<int>` 按顺序记录已赋值的变量编号。

新赋值时追加到末尾；回退时从末尾逐个撤销，因此它起到栈的作用。冲突分析时，也可以从后向前查看赋值顺序。

### 4. 每轮选择的起始位置

使用一个 `vector<int>`，记录每次主动选择开始前，赋值记录的长度。

例如，某次选择开始前已经有 5 条赋值记录，就记下 5。需要撤销这次选择及后续操作时，将赋值记录恢复到这个长度即可。

### 5. 冲突分析的临时标记

使用标记数组 `seen`，记录某个变量是否已经在本次冲突分析中处理过，避免重复处理。

另外使用临时 vector 保存正在推导的新子句，分析完成后将它加入子句集合。
